# /decide — зафиксировать решение как ADR
Превращает принятое решение в архитектурную запись (ADR) — короткий документ «что решили, почему и какой ценой». Работает как протокол: фиксирует контекст и аргументы, чтобы через полгода не спорить заново и не передумывать вслепую. Поддерживает статусы и связь с проектом.

## Как работает
1. Берёт суть решения и оформляет в формате Y-statement («В контексте … перед лицом … мы решили … чтобы … смирившись с …») или Nygard (Context/Decision/Status/Consequences).
2. Создаёт файл `_BRAIN/Решения/ADR-NNN_<слаг>_<ГГГГ-ММ-ДД>.md` со следующим свободным номером.
3. Ставит статус: `proposed` (обсуждается), `accepted` (принято), `superseded` (заменено другим ADR).
4. При замене старого решения проставляет взаимные ссылки superseded ↔ supersedes.
5. Добавляет вики-ссылку на ADR из карточки проекта `Проекты/<имя>/README.md` (в хранилище второго мозга; путь к хранилищу — в `~/.claude/CLAUDE.md`).
6. Возвращает путь к ADR и его статус.

## Пример
```
> /decide делаем цену курса 4900₽ вместо 5900, чтобы поднять конверсию
```
Создаёт `_BRAIN/Решения/ADR-007_цена-курса_2026-06-14.md`:
```
Статус: accepted
В контексте запуска курса, перед лицом низкой конверсии,
мы решили цену 4900₽ (вместо 5900), чтобы поднять конверсию,
смирившись с меньшей маржой с продажи.
```
Ответ: «ADR-007 (accepted), вписал ссылку в карточку проекта.»
