# /panel — совет из нескольких голов

Прогоняет твоё решение через 3-5 разных ролей — скептик, оптимист, финансист, клиент, оператор — и сводит их в один вывод. Каждая роль смотрит со своей колокольни и опирается на факты из хранилища, а не на общие слова.

## Как работает
1. Определяет тип решения и подбирает релевантные роли (по умолчанию: скептик, оптимист, финансист, клиент).
2. Для каждой роли греп по хранилищу за фактами под её угол: финансист тянет цены из `STACK.md`, клиент — позиционирование из `STATE.md` и заметок.
3. Каждая роль даёт короткий вердикт + 1-2 аргумента со ссылкой.
4. Сводка: где роли сошлись, где конфликт, и итоговая рекомендация с условием.
5. Помечает, какой роли не хватило данных в хранилище.

## Пример
`/panel стоит ли брать этого подрядчика`
> - Скептик: в заметках нет проверенных кейсов — риск срыва срока.
> - Оптимист: разгрузит тебя под главный приоритет (см. `STATE.md`).
> - Финансист: сверь ставку с бюджетом (`STACK.md`) — не должно ломать юнит-экономику.
> - Клиент: качество влияет на бренд — халтура заметна.
> Свод: брать на пилот с фиксированным узким объёмом и предоплатой по этапу. Согласны 3 из 4, скептик снимает возражение при пилоте.
