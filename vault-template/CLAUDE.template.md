# Второй мозг — операционная инструкция (читается каждой сессией)

> Рабочий метод. Личное наполняется интервью; здесь — как агент работает с твоим хранилищем.

## Старт сессии (Tier-навигация — читать по уровням, не грузить всё)
1. **Tier 1 (всегда):** `hot.md` (где остановился) → `INDEX.md` (карта) → горячее ядро (`STATE.md`, `STACK.md`). Одной строкой: «Контекст загружен: [активные проекты]».
2. **Tier 2 (по задаче):**
   - про проект → его `README` сначала, потом подпапки;
   - «все заметки по X» → grep по тегу `#X`, не читать `Заметки/` целиком;
   - «почему решили X» → grep по `Решения/` перед ответом;
   - стратегия → только файл с `# АКТУАЛЬНАЯ` (максимальная версия).
3. **Tier 3 (игнор без просьбы):** `Архив/`, `Выводы/` старше 30 дней, стратегии `# АРХИВ`, личные папки.

## Память — записывать находки обратно (по сигналу, не каждый ход)
- Записи в память (заметки/решения/выводы) делаю **без спроса**, сообщая одной строкой «сохранил в [путь]». Необратимое/наружу — подтверждаю.
- **По сигналу:** сохраняем на «готово/спасибо» или после заметного блока. В моменте — короткий `append`; дорогую переплавку страниц — батчем на `/review`/`/health`. (Append дёшев, rewrite дорог — не жжём токены.)
- В конце сессии обнови `hot.md` (3–6 строк resume: над чем работали, следующий шаг, тронутые файлы).
- Не дублировать инфу между файлами (CONTEXT / MEMORY / PROJECTS).

## Правила записи (куда что)
- **Заметки** — пишу сам, если появился фреймворк/метод/цифра/решение/чеклист/находка-ресёрча. Формат: первая строка теги `#источник #тема`, резюме 2–3 строки, содержание. Планка низкая, дубли не плодим. Инфра/ключи → `STACK.md`, не в Заметки.
- **Решения (ADR)** — на решение, на которое сошлются позже. Y-statement: «In context of X, facing Y, we chose Z to achieve W, accepting V» (или Nygard: Title/Status/Context/Decision/Consequences). Статусы: proposed/accepted/superseded/deprecated. 5–10 строк.
- **Выводы** — итог сессии: что сделали / что решили / следующие шаги.
- **Стратегии** — версии; первая строка `# АКТУАЛЬНАЯ` или `# АРХИВ`; новая версия → старую в `# АРХИВ`.
- **Проекты (канбан)** — статусы 🔴идея/🟡план/🟢актив/⏸пауза/✅закрыт; у каждого Цель / Следующий шаг / Блокеры / Дата.
- **Postmortem** — на закрытие проекта или публикацию + метрики: Timeline / План vs Факт / Root cause / Что повторить / Что не повторить.
- **Встречи** — расшифровка → файл с frontmatter (date/type/project/participants/confidential/tags); `confidential: true` наружу не уходит.

## Где что хранить — заметки vs код/сайты/большие файлы (ВАЖНО)
- **Это хранилище (vault) — только текст и заметки.** Оно лёгкое и синхронизируется в облако. Сюда: заметки, решения, итоги, `README` проектов со ссылками.
- **Код, сайты, сборки, большие ассеты — НЕ в хранилище.** Они живут в отдельной **рабочей папке** (путь — в `STACK.md` → «Рабочая папка проектов»), по подпапке на проект: `<рабочая папка>/<проект>/`. Иначе хранилище раздуётся (сайт — это гигабайты) и забьёт облако.
- Когда создаёшь артефакты проекта (код, сайт, билд, медиа) — создавай их **в рабочей папке проекта**, а не в vault. В vault про этот проект держи только заметку/`README` со **ссылкой** на рабочую папку.
- **Рабочую папку спрашивай по факту:** если она ещё не задана в `STACK.md`, а человек просит что-то построить — спроси один раз: «Где держать рабочие файлы проектов (код/сайты)? По умолчанию `~/Projects`, вне облака» — и запиши путь в `STACK.md`. Внутри неё сам раскладывай по подпапкам-проектам.

## Разделение «исследование vs личные рекомендации» (если делишься файлами наружу)
- **Исследовательские** документы (анализ рынка, разбор конкурентов, юнит-экономика, кейсы) — нейтральный тон, третье лицо, без «ты», без твоих личных проектов/финансов и советов лично тебе. Чтобы файл можно было отправить как есть.
- **Личные рекомендации** (оценка фита, варианты лично для тебя, сравнение с твоими активами) — в отдельный файл `[проект]/Личные_рекомендации_[дата].md`.

## Лимиты размера (следить, предлагать чистку)
- Фокус-файл ≤ ~100 строк, индексы памяти ≤ ~150. Старое — в `Архив/`. Горячее ядро держим маленьким (грузится всегда).

## Конвенции
- Даты `ГГГГ-ММ-ДД` · версии `v1/v2/v2.1` · теги первой строкой `#источник #тема` · README в папке = что тут / актуально / архив.

## Токен-эффективность
- Читай `index`/`hot` сначала (карта + недавнее), а не весь vault. Горячее ядро маленькое.

## Поведение (метод)
- **Критическая оценка до выполнения:** если подход явно ведёт не туда (анти-паттерн, неверный формат, есть лучше) — предупреди ОДИН раз до старта, кратко: «Прежде чем делать — обрати внимание: [проблема]. Продолжать, скорректировать или обсудить?». Подтвердил/отмахнулся — выполняй молча. Чисто механические задачи — без предупреждений.
- **Критическое мышление:** не хвалить автоматически; слабую идею/нереалистичный план назвать прямо — что не так и что лучше. Похвала — при реальном основании.
- Не додумывать молча · не оверинженерить · не лезть в несвязанное.
- Прямо, без воды.

## Исследование (verification-first)
- Каждый факт в research-заметке несёт **источник + дату** `(на ГГГГ-ММ, источник)` + уровень уверенности (подтверждено/вероятно/не проверено). Устаревшее флагуем. Активная пересверка `/verify` — по запросу (стоит токенов).

## Правила-константы
- Секреты в `.md` не пишем — только указатели, где лежат. Даты `ГГГГ-ММ-ДД`. Не выдумывать факты.
